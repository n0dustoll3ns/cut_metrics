## 1. Структура навигации

Нижняя навигация: **4 вкладки** — Сегодня · Тренд · Саммари · Настройки.

| Вкладка | Содержимое |
|---|---|
| Сегодня | Сглаженный вес (60px, Deep Ink), сырое значение за сегодня, график веса+EMA за 30 дней, кнопка «Открыть саммари» (primary), карточки метрик Фазы 3 (Вес, Шаги) |
| Тренд | Сегменты Неделя / Месяц / 3 месяца, график веса+EMA (тап по точке → карточка), блок «Среднесуточные показатели»: Сон (ч), Шаги, Активность (ккал) |
| Саммари | Еженедельное саммари (см. §4) |
| Настройки | Целевой темп (слайдер), уровень активности (1–5). Без кнопки «Сохранить» — мгновенное применение |

«Весь срок» как сегмент Тренда — **убран** по решению пользователя (полная история = тяжёлый
запрос + полный пересчёт EMA); максимум — 3 месяца.

Решения по Фазе 3 (сохранено): карточки подтверждения остаются на «Сегодня» (инлайн) и
открываются тапом по точке графика на «Тренде».

## 2. Активность и расход калорий

`EXERCISE_TIME` и `ACTIVE_ENERGY_BURNED` НЕ используются. Модель предельно простая:

### 2.1 Формула

```
kcalFromSteps = шаги × вес(кг) × 0.0005          // ≈400 ккал на 10 000 шагов при 80 кг
kcalFromTraining = kcalPerKgPerDay(уровень) × вес(кг)
kcalPerDay = kcalFromSteps + kcalFromTraining
```

- Вес для формулы — самый свежий резолвленный вес из кеша. Нет ни одного веса → калории «—».
- День без записи шагов считается 0 шагов (kcalFromSteps = 0), добавка уровня начисляется всегда.

### 2.2 Уровни активности (1–5), коэффициенты и тексты

| Ур. | Название | Текст | ккал/кг/день | Пример при 80 кг |
|---|---|---|---|---|
| 1 | Минимальная | Без тренировок | 0.0 | +0 ккал |
| 2 | Лёгкая | 1–2 тренировки в неделю | 1.5 | +120 ккал |
| 3 | Умеренная | 3–4 тренировки в неделю | 3.0 | +240 ккал |
| 4 | Высокая | 5–6 тренировки в неделю | 4.5 | +360 ккал |
| 5 | Очень высокая | Тренировки каждый день | 6.0 | +480 ккал |

Дефолт — уровень 1 (консервативный, не завышаем расход у нового пользователя).

### 2.3 Среднесуточные на «Тренде»

- **Сон** — среднее по ночам с данными (ночи без трекинга исключаются из знаменателя).
- **Шаги** — среднее по дням с записями.
- **Активность** — «≈ N ккал»: среднее `kcalPerDay` по ВСЕМ дням периода (включая дни без шагов).

Ручной ввод шагов уже реализован (Фаза 2/3, `writeManualRecord` → Health Connect).

## 3. Сон

- `SleepAnalyzer` перенесён из `lib/old_proj/domain/sleep.dart` (решение С1) с адаптациями.
- Правило дня сна сохранено: интервал, начавшийся после 12:00, относится к следующему дню (С3).
- Типы (С2): стадии `SLEEP_DEEP + SLEEP_LIGHT + SLEEP_REM` **плюс `SLEEP_ASLEEP`** с приоритетом:
  если за ночь есть `SLEEP_ASLEEP` — `total` равен ему, иначе сумма стадий.
- **Слияние интервалов по слоям**: стадии мержатся отдельно от `ASLEEP` (общий интервал сна
  содержит внутри стадии — сквозной merge обрезал бы стадии).
- Результат — только ночи с `total > 0` (пустые ночи не попадают в кеш).
- Сон read-only: без карточек подтверждения и беджей (С5). Разрешения уже запрошены (`kSleepTypes`).
- Диапазон чтения — с запасом −1 день (ночь пересекает полночь).

## 4. Саммари

- **Пересчёт при каждом открытии вкладки** за скользящие 7 дней (U3, отменяет еженедельный цикл
  A.6 исходной спеки). Готовность: ≥3 взвешиваний (сырых точек веса) в окне.
- Не готово при попытке перехода: снекбар «Недостаточно данных — нужно ≥3 взвешивания за неделю»,
  вкладка не открывается.
- При показе записывается `lastSummaryShownDate` (хранится, но не гейтит показ — на будущее).
- Содержимое по макету: диапазон дат, точка-статус (steady/alert) + заголовок, темп %/нед
  (Cobalt, 44px) + «±N кг за неделю», вывод одним предложением, разделитель, «Рекомендация на
  следующую неделю» + текст.
- Сравнение с целью — по модулю фактического темпа (A.3): набор веса при цели снижения
  квалифицируется как tooSlow (снижения недостаточно).
